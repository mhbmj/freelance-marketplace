# پایگاه داده بازار کار فریلنسری (Freelance Marketplace)

این پروژه مربوط به **تمرین دوم درس آزمایشگاه مهندسی نرم‌افزار** (مدرس: مهندس میهن‌پور) است.

* **نام تیم:** مهتاب
* **عضو تیم:** مهتاب مروج

---

## ۱. معرفی پروژه

هدف این پروژه، طراحی پایگاه داده برای یک سامانه فریلنسری است. در این سامانه:
* کاربران ثبت‌نام می‌کنند و حساب کاربری دارند.
* هر کاربر عادی می‌تواند هم به عنوان **کارفرما** پروژه ثبت کند و هم به عنوان **فریلنسر** برای پروژه‌های دیگران پیشنهاد بفرستد.
* مدیران (Admin) حساب جداگانه با دسترسی نظارتی دارند.
* کارفرما پروژه‌ای با بودجه، نوع قیمت (ثابت یا ساعتی) و مهارت‌های لازم تعریف می‌کند.
* فریلنسرها برای پروژه‌های باز پیشنهاد قیمت و زمان ارسال می‌کنند.
* کارفرما پیشنهادها را بررسی کرده و حداکثر یکی را می‌پذیرد.

---

## ۲. پایگاه داده انتخابی و دلیل انتخاب

* **پایگاه داده:** **PostgreSQL**
* **دلایل انتخاب:**
  1. پایداری و استاندارد بودن و پشتیبانی کامل از کلیدهای اصلی، خارجی و محدودیت‌ها (CHECK و UNIQUE).
  2. امکان ایجاد ایندکس شرطی برای قاعده «حداکثر یک پیشنهاد پذیرفته شده برای هر پروژه».
  3. هماهنگی کامل با فریم‌ورک‌های بک‌اند نظیر Django.

---

## ۳. نحوه راه‌اندازی و اجرای فایل‌ها

فایل‌ها به ترتیب زیر در ابزار خط فرمان `psql` یا رابط گرافیکی `pgAdmin` اجرا می‌شوند:

### گام اول: ساخت ساختار جداول (Schema)
این فایل تمام ۱۲ جدول، کلیدها، محدودیت‌ها و تریگرها را می‌سازد:
```bash
psql -U postgres -d freelance_db -f database/schema.sql
```

### گام دوم: وارد کردن داده‌های نمونه (Seed)
این فایل داده‌های اولیه (کاربران، پروژه‌ها، مهارت‌ها و پیشنهادها) را درج می‌کند:
```bash
psql -U postgres -d freelance_db -f database/seed.sql
```

### گام سوم: اجرای کوئری‌های کاربردی (Queries)
این فایل ۴ کوئری اصلی خواسته شده در صورت تمرین را اجرا می‌کند:
```bash
psql -U postgres -d freelance_db -f database/queries.sql
```

### گام چهارم: اجرای آزمون محدودیت‌ها (Tests)
این فایل صحت محدودیت‌ها (رد مقادیر منفی، ایمیل تکراری و ...) را تست می‌کند:
```bash
psql -U postgres -d freelance_db -f database/tests.sql
```

## ۴. ساختار جداول پایگاه داده

1. **users:** اطلاعات کاربران (نام، نام خانوادگی، ایمیل یکتا، رمز عبور، وضعیت و تاریخ‌ها).
2. **admins:** مشخص‌کننده حساب‌های مدیر و تاریخ اعطای دسترسی.
3. **user_profiles:** پروفایل تکمیلی کاربر (عنوان شغلی، بیوگرافی، شهر).
4. **portfolios:** نمونه‌کارهای فریلنسر.
5. **certificates:** مدارک و گواهینامه‌های فریلنسر.
6. **categories:** دسته‌بندی پروژه‌ها (مانند وب، موبایل، هوش مصنوعی).
7. **skills:** مهارت‌ها (مانند Python، React، PostgreSQL).
8. **user_skills:** جدول واسط چندبه‌چند بین کاربر و مهارت‌هایش.
9. **projects:** پروژه‌های ثبت‌شده توسط کارفرما (با بودجه، نوع پرداخت و وضعیت).
10. **project_categories:** جدول واسط چندبه‌چند بین پروژه و دسته‌بندی‌ها.
11. **project_skills:** جدول واسط چندبه‌چند بین پروژه و مهارت‌های لازم.
12. **proposals:** پیشنهادهای ارسالی فریلنسرها برای پروژه‌ها.

---

## ۵. تصمیم‌های طراحی و قواعد کسب‌وکار

* **نقش کارفرما و فریلنسر:** در جدول `users` نقش ثابت ذخیره نشده است؛ هر کاربر اگر در جدول `projects` پروژه‌ای بسازد نقش کارفرما پیدا می‌کند و اگر در جدول `proposals` پیشنهادی بفرستد در نقش فریلنسر عمل می‌کند. در فایل `seed.sql` کاربر «سارا احمدی» هم کارفرماست و هم فریلنسر.
* **نقش مدیران (Admin):** در جدول مجزای `admins` ذخیره می‌شوند و تاریخ اعطای دسترسی در آن ثبت است.
* **محدودیت مقادیر مثبت:** بودجه و مبلغ پیشنهاد باید بزرگتر از صفر باشند (`CHECK > 0`).
* **حداکثر یک پیشنهاد پذیرفته شده:** با یک ایندکس شرطی (`WHERE status = 'ACCEPTED'`) تضمین شده است که در هر پروژه حداکثر یک پیشنهاد پذیرفته شود.
* **منع پیشنهاد روی پروژه خود:** کارفرما نمی‌تواند روی پروژه‌ای که خودش تعریف کرده پیشنهاد ارسال کند.
* **تغییر خودکار وضعیت:** با پذیرفته شدن پیشنهاد، وضعیت پروژه به طور خودکار به `IN_PROGRESS` تغییر می‌یابد.

---

## ۶. وضعیت‌های موجودیت‌ها (Status)

* **وضعیت حساب کاربر:** `ACTIVE` (فعال)، `INACTIVE` (غیرفعال)، `SUSPENDED` (مسدود).
* **وضعیت پروژه:** `DRAFT` (پیش‌نویس)، `OPEN` (باز برای دریافت پیشنهاد)، `IN_PROGRESS` (در حال انجام)، `COMPLETED` (تکمیل شده)، `CANCELLED` (لغو شده).
* **وضعیت پیشنهاد:** `PENDING` (در انتظار)، `ACCEPTED` (پذیرفته شده)، `REJECTED` (رد شده)، `WITHDRAWN` (انصراف).
